# Worthflow

A local-first personal savings and finance dashboard. Import your existing net-worth
spreadsheet, update it monthly from the dashboard or the CLI, track trends per account
and across your whole portfolio, and view everything in EUR, USD, or PLN.

Your financial data never leaves your machine unless you explicitly turn on and
configure an external AI provider (off by default — see [AI configuration](#ai-configuration)).

## Architecture at a glance

```
backend/app/
  domain/          Pydantic schemas (accounts, snapshots, currencies)
  database/        SQLAlchemy models + session (SQLite)
  services/        business logic — shared by the API and the CLI
    accounts_service.py, snapshots_service.py, users_service.py
    exchange_rates/   ExchangeRateProvider abstraction + Frankfurter impl + DB-cached service
    calculations/     deterministic math: trends, growth, allocation (no AI here)
    import_excel/     mapping config -> parser -> preview/commit importer (fast path, no AI)
    import_ai/        arbitrary file -> text -> AI interpretation -> preview/commit importer
    ai/               AIProvider (analysis, stub) + ImportInterpreterProvider (Anthropic) +
                       privacy-gated AIAnalysisService / import_ai.service gating
  api/             FastAPI routers — thin, delegate everything to services/
backend/cli/       Typer CLI — calls the exact same services/ as the API
backend/alembic/   versioned DB migrations
frontend/          React + TypeScript dashboard (Vite, Recharts)
data/
  private/         YOUR data — gitignored, never committed (finance.db, imports/, exports/)
  demo/            generated by scripts/seed_demo.py — fictional data only
docs/architecture.md   deeper design notes and the Excel -> DB mapping
```

The API and CLI are two thin front ends over the same `app/services/*` layer —
neither contains business logic itself. See [docs/architecture.md](docs/architecture.md)
for the full design rationale, the database schema, and how the source Excel file maps
onto it.

## Setup

### Prerequisites

- Python 3.10+
- Node.js 18+ (for the dashboard)

### Backend

```bash
cd backend
python -m venv .venv
.venv/Scripts/pip install -e ".[dev]"
copy ..\.env.example ..\.env
.venv/Scripts/alembic upgrade head
```

This creates `data/private/finance.db` — your real, local, gitignored database.

Run the API:

```bash
.venv/Scripts/uvicorn app.main:app --reload
```

### Frontend

```bash
cd frontend
npm install
npm run dev
```

Open http://localhost:5173. The dev server proxies `/api` to `http://127.0.0.1:8000`.

### Try it with demo data first (no real data required)

```bash
cd backend
.venv/Scripts/python scripts/seed_demo.py
```

Then set `DATABASE_URL=sqlite:///./data/demo/demo.db` in `.env` (or point a second
terminal's env var at it) before starting the API, so you're browsing fictional
"Demo Checking" / "Demo Savings" / "Demo Brokerage" / "Demo Crypto Wallet" accounts,
never your own.

## Importing your data

The dashboard's **Import** tab has two ways in, both preview-then-confirm — nothing is
written until you explicitly say so:

**AI-assisted import** (any `.xlsx`/`.xlsm`/`.csv`, any layout) — upload a file, an AI
reads it and proposes accounts + dated values, you review and edit the proposal (name,
currency, type, asset class, which accounts/whether to include them, with the raw
entries visible to check), then confirm. This is off by default — it sends the file's
contents to an external AI provider, which requires explicit opt-in (see
[AI configuration](#ai-configuration)). Without it, the tab tells you exactly what to
set in `.env`.

**Quick import** (exact "Raw data" layout only) — free, instant, no AI, no network
call. Works only for the one specific accounts-as-rows / months-as-columns sheet shape
this project started from (see [docs/architecture.md](docs/architecture.md) for the
exact mapping). Unrecognized rows produce a warning and are skipped, never guessed at.

The CLI always uses the fast/deterministic path (AI-assisted import is dashboard-only
today):

```bash
finance import ./data/private/imports/your-file.xlsx
```

## Updating monthly data

**Dashboard → Monthly values tab** — an Excel-style grid, one row per account, one
column per month, in each account's own currency. It's read-only until you press
**"🔒 Enable editing"** (a deliberate confirmation step before any cell becomes
clickable); click a value to add or correct it.

**Dashboard → Accounts tab** — browse accounts, tick the box next to any number of them
to plot their trends together on one chart (useful for comparing accounts).

**CLI:**

```bash
finance snapshot add "Revolut" 2450.00 --date 2026-09-30
finance status
finance analyze
```

Every write path — the Monthly Values grid, the CLI, and both import flows — goes
through the same rule: adding a value for a month that doesn't have one yet is
additive; a month that already has a value gets corrected in place, never duplicated.

## CLI reference

| Command | Purpose |
|---|---|
| `finance import <file>` | Preview then commit an Excel import |
| `finance snapshot add <account> <value> [--date]` | Add/correct a monthly value |
| `finance snapshot list [--account-name]` | List recorded snapshots |
| `finance accounts list` / `accounts add` / `accounts deactivate` | Manage accounts |
| `finance rates [--on-date]` | Fetch and cache exchange rates |
| `finance status` | Quick summary: accounts, latest snapshot, current total |
| `finance analyze` | Deterministic trend summary (not AI — see below) |

## How currency conversion works

Every snapshot keeps its **original value and currency** — nothing is converted and
overwritten. Display currency is applied at read time using a historically accurate
rate for that snapshot's date, fetched from [Frankfurter](https://frankfurter.dev)
(ECB-backed, free, no API key) and cached in `exchange_rates` so:

- looking at last March's total always uses last March's real rate, not today's
- the app keeps working offline / through API outages using the last known-good
  cached rate (and says so, rather than pretending it's live)

The provider is swappable — see `app/services/exchange_rates/provider.py`.

## AI configuration

Two independent AI features share the same off-by-default privacy gate:

- **AI-assisted import** (Import tab) — reads an uploaded file's contents and proposes
  an account/snapshot mapping. **Implemented, works today** once configured below.
- **AI analysis** (`app/services/ai/service.py`) — narrative interpretation of your
  already-computed metrics. A Phase-7 extension point; no provider beyond a local
  no-op is wired up yet.

Both require explicit opt-in via `.env` — nothing is sent anywhere by default:

```env
AI_ANALYSIS_ENABLED=true
AI_PROVIDER=anthropic        # only "anthropic" is implemented so far
AI_ALLOW_EXTERNAL_DATA=true  # required before ANY data leaves your machine
AI_MODEL=claude-sonnet-5
ANTHROPIC_API_KEY=...
```

`build_import_interpreter()` (`app/services/import_ai/service.py`) and
`AIAnalysisService` (`app/services/ai/service.py`) both enforce this: without both
flags set, they raise a clear "not configured" error instead of silently failing —
the Import tab surfaces that error directly, telling you what to set. AI never does
arithmetic itself: import-interpretation only proposes a *mapping* (which you review
before anything is saved), and analysis only ever receives pre-computed deterministic
metrics from `app/services/calculations/`.

The import interpreter is a swappable interface too — see
`app/services/ai/import_interpreter.py` — so another provider can be added the same
way `AnthropicImportInterpreter` was, without touching the API or frontend.

## Privacy & backups

- `data/private/` (your database, imports, exports) and `.env` are gitignored — see
  `.gitignore`. Never commit them.
- To back up: copy `data/private/finance.db` somewhere safe. It's a single file.
- To migrate to another machine: copy `data/private/` and `.env`, then
  `alembic upgrade head` to apply any migrations you haven't run yet.
- To run your own instance from this codebase: clone it, follow Setup above — your
  data directory is separate from the application code by design, so pulling
  updates never touches your data.

## Testing

```bash
cd backend
.venv/Scripts/pytest
```

Tests run against an isolated in-memory SQLite database and a fake exchange-rate
provider — they never touch `data/private/finance.db` or the network.
